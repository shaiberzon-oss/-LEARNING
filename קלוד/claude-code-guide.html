📋 איך Claude מכיר את הפרויקט שלך?
💡 אנלוגיה
דמייני/י שכרת/ת עובד חדש. בלי שום הכנה, הוא/היא לא יודע/ת כלום — "מה שפת התכנות? מה שם בסיס הנתונים? מה הכללים שלנו?". עם קובץ CLAUDE.md — זה כמו לתת לו/לה חוברת עובד מפורטת ביום הראשון. הוא/היא קורא/ת אותה פעם אחת ויודע/ת הכל מהרגע הראשון.
CLAUDE.md הוא קובץ טקסט פשוט שנמצא בתוך תיקיית הפרויקט. Claude קורא אותו בתחילת כל שיחה — וכך "זוכר" מי אתה/את, מה הפרויקט, ומה הכללים. אין צורך להסביר שוב ושוב.

# מדריך לפרויקט "חנות האינטרנט"

## שפת תכנות: Python + FastAPI
## בסיס נתונים: PostgreSQL
## שפת ממשק: תמיד בעברית

Prod (פרודקשן) = הגרסה החיה של התוכנה שמשתמשים אמיתיים משתמשים בה. שינוי בה ללא זהירות עלול לשבור את האתר לכולם.
שלוש רמות הוראות לפרויקטים שונים:
🌍

רמה גלובלית — כל המחשב

הוראות שתקפות בכל פרויקט שתפתח/י. לדוגמה: "תמיד כתוב הסברים בעברית" או "אל תשתמש בפונקציות שמיושנות". נשמר אצלך במחשב ולא עולה לאינטרנט.

📁

רמת הפרויקט — לכל הצוות

ה-CLAUDE.md שבתיקיית הפרויקט. עולה ל-Git (מערכת שיתוף הקוד) יחד עם שאר הקוד — כך כל מפתח בצוות שעובד עם Claude מקבל אותן הוראות ואותו הקשר.

👤

רמה אישית — רק לך

העדפות אישיות שלך שאין צורך לשתף עם הצוות. לדוגמה: "תמיד הצע לי שלוש אפשרויות לפני שבוחר/ת". לא עולה לשרת — נשאר אצלך בלבד.

טיפ מתקדם: פקודת /init גורמת ל-Claude לסרוק את כל הפרויקט בפעם הראשונה וליצור קובץ CLAUDE.md אוטומטי — כך שלא צריך לכתוב אותו מאפס!

🪝 Hooks — חוקים אוטומטיים
💡 אנלוגיה
כמו מנגנון בטיחות במכונית: לפני שהמנוע מתניע — בודק שחגורת הבטיחות קשורה. Hooks הם חוקים כאלה ל-Claude: "לפני שאתה עורך קובץ — הרץ בדיקת שגיאות" או "אחרי שעשית שינוי — ודא שלא שכחת לעדכן את הטסטים".
Hook (ווו = "לתפוס") = פיסת קוד שרצה אוטומטית לפני או אחרי שClaudeמבצע פעולה. הם מאפשרים להגדיר חוקים קשיחים שClaudeלא יכול לעקוף — גם אם שכח, גם אם ממוקד בדבר אחר.

🔍

Hook בדיקת שגיאות

מה זה שגיאות טיפוסים?
בשפות תכנות מסוימות (TypeScript, Java), כל משתנה מוגדר מה "סוג" הערך שלו — מספר, טקסט, תאריך. כשClaude משנה פונקציה אבל שוכח לעדכן שימושים אחרים בה, ה-Hook מגלה זאת מיד ומדווח לClaude לתקן.

🔒

Hook הגנה על סודות

מה זה .env?
קובץ .env מכיל "מפתחות" לשירותים — כמו סיסמת המייל שלך, מפתח API לתשלומים, ומפתח הגישה לבסיס הנתונים. Hook מונע מClaude לקרוא קובץ זה בטעות ולחשוף את הסודות שלך.

🔄

Hook מניעת כפילויות

כשClaude עמוס במשימה, הוא לפעמים כותב קוד שכבר קיים במקום אחר. Hook זה שולח instance (עותק) נפרד של Claude לבדוק אם הקוד החדש כבר קיים — ואם כן, עוצר ומכוון את Claude לשתמש בקיים.

מתי Hooks רצים? יש שני סוגים:
• לפני הפעולה (Pre-hook) — יכול לעצור את Claude לגמרי אם משהו לא בסדר
• אחרי הפעולה (Post-hook) — רץ אחרי, יכול לתת משוב אבל לא יכול לבטל

🤔 מה ההבדל בין Planning לבין Thinking?
שאלה שמבלבלת הרבה אנשים — הנה ההסבר הפשוט:
🗺️ Planning (תכנון)
למה: משימות שמשפיעות על הרבה קבצים
מה עושה: בונה רשימת מטלות מסודרת, מגדיר סדר פעולות
דוגמה: "שנה את פורמט התאריך בכל האתר" — נוגע ב-20 קבצים, צריך סדר
= רוחב · ניהול תהליך מורכב
VS
🧠 Thinking (חשיבה)
למה: גם משימות קטנות עם לוגיקה מורכבת
מה עושה: שוקל עומק, שיקולים, אפשרויות, edge cases
דוגמה: "הוסף מערכת תגובות" — קובץ אחד, אבל דורש חשיבה על DB, ביטחון, ביצועים
= עומק · פתרון בעיה מורכבת
🏆 המלצה: למשימות מורכבות — השתמש בשניהם יחד! Planning לארגון הסדר, Thinking לעומק הפתרון.
🗣️ מילות מפתח שעובדות — ושלא עובדות
יש אנשים שמנסים להגיד ל-Claude "think hard" או "think more" כדי לשנות את רמת המאמץ. לפי התיעוד הרשמי — זה לא ממופה לאפורט מסוים.
⚠️ לא מבטיח effort level:
"think", "think hard", "think more", "think carefully"
Claude עשוי לחשוב — אבל לא בהכרח ב-High effort
✅ מפעיל High effort בפועל:
"ultra think about this problem"
המילה "ultra" — הכלל היחיד שמאלץ את הרמה הגבוהה ביותר
📖 דוגמה לשימוש נכון:
# הכי חזק — Ultra Think:
"ultra think about the following
 problem and help me solve it:
 [תיאור הבעיה]"

# הגדרת תקרה עם effort:
effort → high → אז שאל את השאלה
💡 יתרון חשוב שלא כולם יודעים: כל תוכן החשיבה הפנימית של Claude (ה-Thinking) נמחק אוטומטית מהקשר השיחה ברגע שהוא הגיע למסקנה. כלומר — Claude חושב לעומק, אבל "הזיכרון" של השיחה לא מתמלא בחשיבה הזו. זה שומר על הקשר נקי ויעיל, וחוסך טוקנים לטווח הארוך.
🧠
Claude Code הוא עוזר AI שפועל — לא רק מדבר.
הוא קורא קבצים, כותב קוד, מריץ בדיקות ומתקן שגיאות לבדו.
